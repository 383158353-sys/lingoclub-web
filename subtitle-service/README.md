# LingoClub Subtitle Service

Independent Linux container that fetches existing YouTube captions only. It never downloads video or audio. It does not accept browser credentials or YouTube cookies.

## Runtime contents

- Node.js 24 HTTP API and subprocess orchestration.
- yt-dlp stable pinned to `2026.08.19`, installed with its default EJS package.
- bgutil PO Token Provider/plugin pinned to `2.0.1`; the local HTTP provider starts inside the same container and the yt-dlp plugin requests tokens automatically.
- VTT parser (JSON3 is also supported when yt-dlp returns that format).

The PO Token provider can generate tokens automatically, but tokens do not guarantee that YouTube will permit a datacenter IP. No personal Google/YouTube cookies are configured or accepted. A `LOGIN_REQUIRED`/bot restriction can therefore still fail; diagnostics report this without trying to bypass it with a personal account.

## Build and run

From the repository root:

```sh
docker build -t lingoclub-subtitle-service ./subtitle-service
docker run --rm --name lingoclub-subtitle-service \
  -p 8080:8080 \
  -e SUBTITLE_SERVICE_KEY='replace-with-a-random-secret-at-least-32-characters' \
  lingoclub-subtitle-service
```

The key is required and is never logged. In a hosted container platform, set it in that platform's server-side secret settings and expose HTTPS. Do not publish the bgutil provider port; it listens only on container loopback.

Health check:

```sh
curl http://127.0.0.1:8080/health
```

Authenticated subtitle request:

```sh
curl -X POST http://127.0.0.1:8080/transcript \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer replace-with-the-same-secret' \
  -d '{"url":"https://youtu.be/FWPdhRieWOM"}'
```

`POST /transcript` also accepts `{ "videoId": "FWPdhRieWOM" }` instead of a URL. Success returns `{ success, source, videoId, language, isAutoGenerated, subtitles }`, where each subtitle has numeric `start`, `duration`, and `text`. Retryable failures are retried at most three times with a 1.5-second pause. Failure returns `{ success:false, stage, error, diagnostics }` and an appropriate 4xx/5xx status.

## Safety and limits

- Requests must use supported YouTube hosts and a valid 11-character video ID.
- Every yt-dlp call uses `--skip-download`; only subtitle files are written to a unique temporary directory and removed afterward.
- API key authentication uses a constant-time digest comparison.
- Basic per-source-IP rate limit defaults to 10 requests/minute; concurrent extractions default to 3. Configure with `RATE_LIMIT_PER_MINUTE` and `MAX_CONCURRENT_EXTRACTIONS`.
- Request JSON is capped at 16 KiB; yt-dlp subprocesses have bounded time and output buffers.
- Development logs include language availability, selected track/format, yt-dlp exit code, PO-token-provider detection/use and sanitized stderr summaries. They omit cookies, tokens and signed URLs.

## Tests

```sh
npm test
```

These parser/URL tests do not replace live YouTube tests. Real extraction requires building/running the Docker image and network access to YouTube and the PO Token provider.

For isolated remote validation, the repository-root `render.yaml` defines a free Render Web Service. It is not connected to LingoClub and does not change its production API. Render free services can sleep while idle, so use this for validation rather than as a production reliability guarantee.
